# 格式化脚本接入契约（提交前预处理 provider）

> 谁读这份：要让 AI（或提交门禁）自动格式化代码的人。
> 核心理念：**不让你的脚本迁就调用方，而是调用方适配你的脚本**。

---

## 一、这份契约解决什么

`dsh-git-push` 的提交前预处理支持调用**任意脚本**（不要求你发 npm、不要求是 DSH 插件、不要求任何声明）。
本文件规定「你的脚本怎么接收文件列表、怎么返回结果」，以及「调用方怎么适配不同脚本的既有习惯」。

**关键前提**：现成工具的调用习惯是既成事实，改不动。
`gofmt -w a.go b.go` 就是位置参数，`xargs` 就是从 stdin 读，`prettier --write` 就是位置参数 ——
所以**调用方按脚本的习惯喂参数**，而不是要求脚本改造。

---

## 二、输入契约：五种传参方式（脚本选一种，调用方适配）

| `filesMode` | 调用方怎么传 | 典型脚本 |
|---|---|---|
| **`argv`**（默认） | 文件列表**追加到参数末尾** | `gofmt -w <files…>`、`prettier --write <files…>`、`rustfmt <files…>` |
| **`stdin`** | 文件列表**按行写入 stdin** | `xargs -n1 <cmd>`、`while read f; do …; done` |
| **`file`** | 写临时文件，**文件路径作为参数**传给脚本 | 自研分发器（大列表时避免 ARG_MAX） |
| **`env`** | 注入环境变量（见下） | 自己读 `process.env` 的脚本 |
| **`none`** | 什么都不传 | 脚本自己跑 `git diff --name-only` |

**选择判据**：脚本本来怎么接收一堆文件名，就用哪种。**不要为了接入去改脚本的调用方式。**

### 2.1 `env` 模式注入的变量

```bash
PREPROCESS_REPO="/abs/path/to/repo"
PREPROCESS_CHANGED_FILES="src/a.js
src/b.ts
README.md"                          # 换行分隔（文件名可含逗号，故不用逗号）
PREPROCESS_CHANGED_FILES_COUNT="3"
PREPROCESS_CHANGED_FILES_FILE="/tmp/preprocess-xxxx/changed-files.txt"
PREPROCESS_STAGE_PROVIDER="format"
```

- 分隔符用**换行**而非逗号：文件名里可以有逗号，换行几乎不可能
- 同时给 `_FILE`：单个环境变量在 Linux 上有 128KB 上限，大列表必须走文件

### 2.2 占位符（宿主替换，可用于 `args`）

| 占位符 | 替换为 |
|---|---|
| `{repo}` | 仓库绝对路径 |
| `{filesFile}` | 改动文件列表的临时文件路径 |
| `{filesCount}` | 改动文件数量 |
| `{stage}` | 当前阶段序号 |

## 三、输出契约

| 项目 | 要求 |
|---|---|
| **退出码** | `0` = 成功 · `非 0` = 失败（按调用方配置的 `onFail` 决定拦不拦提交） |
| **stdout** | 可选。若输出，应为单行 JSON（便于调用方解析）；纯日志请走 stderr |
| **stderr** | 诊断信息。**用户看不到 stdout 之外的细节时，警告必须写这里** |
| **stdout JSON 字段（可选）** | `{ "changed": ["a.js"], "skipped": [{ "ext": ".go", "reason": "gofmt 未安装" }] }` |

**为什么 stdout 要单行 JSON**：调用方要能在不改你代码的前提下解析结果。散装日志会被当成 JSON 解析失败。

## 四、行为要求（可测）

### R1 只处理传入的文件，不碰全仓
调用方传给你的就是本次改动的文件。**不要自己扩大范围**——全仓格式化一个老仓库会改几千行，提交 diff 变得无法审查。

### R2 幂等：跑两次，第二次零改动
同一份代码运行两次，第二次的改动数必须为 `0`。
违反后果：每次提交都在改文件，且可能引发「格式化 → 检查发现变动 → 又格式化」的循环。

### R3 命令缺失 ⇒ 跳过该扩展名 + 警告，不整体失败
例：`gofmt` 未安装但有 `.go` 改动 ⇒ 跳过 `.go`、往 stderr 写一条警告、**其他扩展名照常处理**、退出码仍为 `0`。

**绝不下载工具**：只在项目已安装对应格式化器时才跑。这是同类工具的共识做法（见 §六 参考实现）。

### R4 尊重项目自身的格式化配置
调用 `prettier` / `rustfmt` / `ruff` 时**不要传自己的 `--config`**，让它们自己去找 `.prettierrc` / `rustfmt.toml` / `pyproject.toml`。
违反后果：用户精心调好的项目格式被你的默认配置覆盖。

### R5 多扩展名要按组独立记账
一个提交里可能同时有 `.go` / `.js` / `.rs`：
- `.go` 成功（改了 3 个）
- `.js` 因 prettier 未装跳过（警告）
- `.rs` 失败（rustfmt 报语法错）

**回执要能表达这三种状态并存**，而不是一个布尔值。否则用户看到"格式化失败"却不知道哪部分成了。

### R6 按扩展名分组批量调用，不要一文件一次
```bash
# ✗ 100 个 .js 文件启动 100 次 npx（每次 1-2 秒 → 200 秒）
npx prettier --write a.js
npx prettier --write b.js

# ✓ 按扩展名分组，一次带多个文件
npx prettier --write a.js b.js c.js …
gofmt -w x.go y.go z.go
```

## 五、扩展名 → 命令映射（推荐基线）

| 扩展名 | 命令 | 备注 |
|---|---|---|
| `.go` | `gofmt -w <files…>` | 幂等，项目配置在 build 时生效 |
| `.rs` | `rustfmt <files…>` | 读 `rustfmt.toml` |
| `.js` / `.ts` / `.jsx` / `.tsx` | `npx prettier --write <files…>` | 读 `.prettierrc` |
| `.py` | `ruff format <files…>` | 读 `pyproject.toml` |
| `.json` / `.md` / `.yml` | `npx prettier --write <files…>` | 可选 |

**路由写成纯函数**（可单测、无副作用）：

```js
// formatterForPath(filePath) → { command, args } | null
function formatterForPath(filePath) {
  const ext = path.extname(filePath).toLowerCase();
  if (ext === '.go') return { command: 'gofmt', args: ['-w'] };
  if (ext === '.rs') return { command: 'rustfmt', args: [] };
  if (['.js', '.ts', '.jsx', '.tsx'].includes(ext)) return { command: 'npx', args: ['prettier', '--write'] };
  if (ext === '.py') return { command: 'ruff', args: ['format'] };
  return null;   // 不认识 ⇒ 不处理（不是错误）
}
```

**不要把这套映射写进调用方（dsh-git-push）的配置** —— 那是你的知识，调用方不该知道 `gofmt` 存在。

## 六、参考实现

| 项目 | 形态 | 可借鉴 |
|---|---|---|
| **hjkl-mangler** | Rust 库 | 核心函数 `formatter_for_path(filePath) → formatter`，纯扩展名分派，内置 8 种工具 |
| **ucf (Universal Code Formatter)** | CLI | 检测扩展名 → 调预设格式化器；**自动读取项目原有配置**（`.prettierrc` / `rustfmt.toml`） |
| **stigmer/format-on-edit** | AI 代理插件（Apache-2.0） | **绝不下载工具**，只在项目已装对应格式化器时才运行 |
| Claude Code 钩子脚本 | bash | 最简路由形态：`case "$file" in *.ts\|*.tsx) npx prettier --write "$file" ;; esac` |

## 七、调用方怎么接你（示例）

```js
// dsh-git-push 的 git_commit_push 调用
git_commit_push({
  repo: '/path/to/repo',
  message: 'feat: xxx',
  preprocessStages: [
    // 你的分发器：自己按扩展名分组
    { command: 'node', args: ['/path/to/formatter.mjs'], filesMode: 'file', onFail: 'warn' },
    // 或者直接调现成工具（argv 模式，最通用）
    { command: 'gofmt', args: ['-w'], filesMode: 'argv', onFail: 'warn' },
    // 检查器：失败即拦截
    { provider: 'audit', onFail: 'block' },
  ],
})
```

也可以在配置文件里长期生效（`preCommit.stages`），调用参数优先级更高。

## 八、自测清单（交付前逐条验）

- [ ] 传 3 个不同扩展名的文件，三种格式化器都被正确调用（或正确跳过）
- [ ] 同一批文件跑两次，第二次改动数 = 0（幂等）
- [ ] 故意卸载 `gofmt`，`.go` 文件被跳过且 stderr 有警告，退出码仍为 0
- [ ] 文件名含空格 / 含逗号 ⇒ 处理正确
- [ ] 只传了 1 个文件 ⇒ 不会去扫全仓
- [ ] 项目有 `.prettierrc` 且与你默认配置冲突 ⇒ 以项目配置为准
- [ ] 传一个语法错误的 `.rs` ⇒ rustfmt 失败，退出码非 0，stderr 有可读原因
