# 版本记录

版本与 `package.json` 的 `version` 一致（契约 C-701）。

| 版本 | 变更 |
| --- | --- |
| 0.2.8 | 跨平台加固 + 去掉本机锚定路径。① `findDshHome` 不再枚举「常见数据根」（`/volume1/@appdata`、`/vol1/@appdata` 这类）去猜套件与版本目录——只认 `DSH_HOME` 环境变量与 `~/.dsh`，因为 DSH 进程里 `DSH_HOME` 本身就是可直接取到的值，猜布局既写死了别人机器的路径、又会在无关目录上空跑 readdir。② 两处取用户主目录/临时目录的方式改用 `os.homedir()` 与 `os.tmpdir()`：原先用 `process.env.HOME` 与 `process.env.TMPDIR || '/tmp'`，在 Windows 上 `HOME`/`TMPDIR` 通常不存在，`join('', '.dsh')` 会退化成相对路径（按当前工作目录找）、`/tmp` 会落到盘根，属于跨平台必错。③ `alignPermissions` 在 Windows 上跳过 chown——那里没有 POSIX 属主语义，逐项尝试只会刷一屏「148 个条目失败」的噪音。④ `DSH_ROOT_CANDIDATES` 补 macOS 与 Windows 候选（用户目录、`~/Applications`、`%LOCALAPPDATA%`、`Program Files`），并在注释里写明「只是探测候选，命中不了还有 env 与上溯兜底」。⑤ `minihost/host.mjs` 也删掉自己那份「套件安装位 node_modules」硬编码清单，改为复用 `locate.js` 的 `findDshRoot()`——同一事实两处表达必然漂移。⑥ 新增门禁 `test/no-hardcoded-paths.test.mjs`：扫描 `lib/`，禁止 `process.env.HOME` / `process.env.TMPDIR` / 本机锚定路径 / 字面量 `/tmp` / Windows 盘符路径；文案里提到路径不算（那不是逻辑），确需探测的安装根候选要带 `dsh-allow-cross-platform` 标记且豁免点不超过 5 处。这类问题单测与 CI 都看不见（测试跑在同一平台、CI 固定 ubuntu），只能靠静态扫描兜住。 |
| 0.2.7 | 修依赖体检的误报：`checkDeps` 原来从 profile 根解析依赖，而插件运行时是从**插件自己所在的目录**向上找，于是「装在插件自己 `node_modules` 里的嵌套依赖」一律被报成缺失（实测某插件每次同步都报 `tree-sitter-wasms 0.1.13` 找不到，实际它在 `local-plugins/<插件>/node_modules/` 下一切正常）。修法是让判定基准与运行时一致：新增 `targetDir` 参数（插件在部署端的实际目录），判定顺序改为「插件内嵌套 → profile 顶层 → 从插件位置做 Node 解析」，`sync_plugin` 与 `verify_plugin` 两处调用都已传入。顺带补两条：`optionalDependencies` 缺席不再算失败（只记 note），目标目录缺 `package.json` 时给出「按 profile 根解析、可能误报嵌套依赖」的提示。对照实测同一个插件：修复后 5 个依赖全部可解析，旧逻辑会误报 2 个（`tree-sitter-wasms` 与 `web-tree-sitter`）。 |
| 0.2.6 | 按《使用摩擦清单》处理六条缺口，并新增残留报告。`minihost` 工具层补齐三个 core 早就有、工具层没暴露的参数：`env`（注入子进程环境变量，此前隔离验证只能绕开工具直接跑 host.mjs）、`force`（已有实例时按新参数重启，此前提示文案让人传一个工具层不存在的参数）、`preview`（根路径直出 HTML，此前只有 CLI 的 `--preview` 能用，想做「一个进程里既有真后端又有真前端」得另起服务）。台账加 `ownerPid`：`list` 缺省只列本进程启动的实例，`all: true` 才列全部并给外来实例标 `foreign`；`stop` 的 `all: true` 只停本进程启动的——多会话共用一台机器时，「全停」理解成全机器就会误杀别人的实例。`preview gen` 的 `spec` 支持 inline JSON 对象或文本（一次性验证界面不必往仓库塞文件），产物落在插件目录且未被 `.gitignore` 忽略时返回 `artifactRisk: true` 并给出两条出路（默认路径不变，只把提示升级成结构化字段）。`sync_plugin` 新增 `stale` 清单：列出「目标里有、源码没有」的残留文件（改名或删文件后的历史遗留），补齐了此前必须手工 `mv` 清旧目录的缺口；只报告不删除，`tools/` 与 `tool/` 下的条目标 `protected: true`——目标里可能有部署方放的东西，删错一次就够受。`node_modules` / `.git` / `.trash` / `.minihost` 不参与残留判定。摩擦清单第 7 条（浏览器内核探测）刻意不做：属 browser-service 职责，在 useful-tools 再造一套会出现两个真相源。 |
| 0.2.5 | 修 `sync_plugin` 抹掉可执行位的静默缺陷。两处成因叠加：① CIFS/SMB 上 `copyFileSync` 必然 EPERM，回退分支用 `readFile+writeFile` 新建文件，只拿到 umask 默认值（通常 644），源侧的 `+x` 就此丢失；② 随后的 `alignPermissions` 按「目标当前 mode」推断该给 755 还是 644，看到已被改成 644 就把它固化成 644 —— 可执行位再也回不来。受害者是插件根 `tools/` 下由部署侧提供的二进制（源码里被 git 忽略、同步不复制它，但权限对齐会遍历整个目标目录），下游表现是「文件存在但不可执行」，功能静默失效且极难回溯到同步这一步。修法：`copyFileCompat` 复制成功后按**源文件**的 mode 补 `+x`（只在源确实带可执行位时补，普通文件仍交给统一策略，避免把源侧 600 这类私有位扩散出去）；`alignPermissions` 新增 `sourceRoot`，有源可依时以源为准，**源里没有的文件（部署侧独有）一律不动 mode**、只对齐属主，并在回执的 `preservedExternal` 与 `notes` 里如实计数说明。`syncPlugin` 调用时已传 `sourceRoot`，未传的旧调用保持原行为仅为兼容。回归测试 5 条锁住：源可执行 → 目标可执行、部署侧独有二进制不被改、源普通文件仍是 644、`alignPermissions` 源缺失时跳过、dryRun 完全不碰权限。 |
| 0.2.4 | `sync_plugin` 三处增强。① 返回的 `files` 改为**只列变动文件**（与目标内容不一致或目标缺失），全量口径移到 `totalCount`，一致数移到 `unchangedCount`，另给 `changedCount`；dryRun 与真写共用同一条逐文件比对路径，预演就能看出「会改哪几个」。② 新增 `target` 目标路径参数，给了就直接同步到该目录（校验存在且是目录），省略保持旧的「DSH_HOME → local-plugins/<插件名>」行为——这是上游模式的地基，因为装机版依赖的真实加载源常在 `node_modules/<插件>`，`local-plugins/` 下根本没有它。`target` 放开任意目录随之补了**插件名防呆**：源与目标都读得到 `package.json.name` 且两者不同就拒绝，放行需显式 `allowMismatch:true`；诱因是宿主运行态闭包陈旧（磁盘副本同步了、进程里 `runSync` 还是启动时 import 的旧实现，旧实现认得 `target` 不认得 `fromGithub`），一次「更新装机版插件」会被静默降级成「拿本地源码覆盖那个插件」，实测只差 `write:true` 就把 63 个文件盖进了别的插件目录；目标没有 package.json 时不拦，不对未知形态瞎猜。③ 新增 `fromGithub` 上游更新模式，`ref` 可空（缺省远端默认分支）。做法是拿 `api.github.com` 的 `git/trees/<ref>?recursive=1` 的 blob sha 与本地文件自算 sha（`sha1("blob <len>\0"+内容)`）**零下载**算出变动清单，再只下载这些文件；每个下载内容仍按 blob sha 校验，镜像给脏内容当场判失败；任一文件取不到就整体不落盘，不留半新半旧。装哪些文件由远端 `package.json` 的 `files` 最小语义决定（精确名 / 目录 / 结尾斜杠 / `!` 否定，顶层 package.json、README、LICENSE、CHANGELOG 始终包含），docs 与 test 不进插件目录；glob 不实现，命中不了如实报告。`truncated` 文件树直接拒绝。真写前把被覆盖的旧文件按相对路径备份到 `<DSH_HOME>/useful-tools/upstream-backup/`，更新记录写 `upstream-records/`（headSha 加每文件 sha）；单次变动超 50 个文件直接拒绝（多半是 `target` 指错目录）。`removed`（本地多余）只报告不删除。实测对象 `MerkyorLynn/dsh-live-compact`（装机 1.0.5 / 上游 main），dryRun 得出 6 变动 + 2 新增 + 5 一致，沙箱真写后逐文件 blob sha 全部对齐、版本号变 1.0.6、备份恰为 6 个被覆盖的旧文件。`node_modules` 装载源不受 hmr 监视，返回值带 `restartNote` 说明要重启宿主才生效。 |
| 0.2.3 | 新增 `github_download`：下载 GitHub 资源（release 资产 / raw 文件 / archive 源码包）时自动选通道。直连 `release-assets.githubusercontent.com`（Release 资产的 302 落地域）会被 TLS SNI 阻断，表现为连接挂住直到超时；公共镜像的**前缀模式**（`https://<镜像>/<原始 URL>`）可取回文件，但手工拼容易写错、也记不住哪家还活着。`channel=auto`（缺省）先探测直连（实测 raw 与 codeload 本机可直连，能省一次镜像中转），不通再按候选清单轮换；候选复用 `github_mirror` 的 `candidates.json`，每次结果回写做失败学习（连续失败 3 次自动停用）。流式落盘不占内存，失败删掉半截文件（文件存在且非零会被后续步骤误判成下载成功），`sha256` 给了就校验。`dryRun=true` 只探通道并给推荐通道；探测镜像时拿到响应头立即断开——实测 `ghfast.top` 不透传 `Range`，用 Range 探测会把整个文件拉下来。接管边界：只覆盖「通过本工具下载」，bash 手敲 `curl` / `wget` 不会被改写；系统级全局接管做不到（阻断在 TLS 层，镜像不是标准 HTTP 代理，只有 MITM 能改写）。 |
| 0.2.2 | DSH 插件规则 9 → 11 条，新增两条 blocker：`dsh/ctx-service-not-injected`（访问 `ctx.<服务>` 但 `inject` 未声明 —— cordis 直接抛 cannot get property，插件整条不激活，用假 ctx 的单测测不出来）、`dsh/plugin-default-export-hides-inject`（入口同时有 `export default` 与命名 `inject`/`apply` —— DSH 装载取 `module.default \|\| module`，命名导出全失效）。两者都要跨行读 `export const inject`，纯逐行正则做不到，因此提交审计侧用脚本扩展 `scripts/audit-ext/dsh-inject-declarations.mjs` 承载。规则带两条保守边界（只查插件入口文件 + 只报已知 cordis 服务名），实测 6 个真实插件零误报。 |

| 0.2.0 | 新增 `github_mirror`：在 git 层写 `insteadOf` 重写（`url.<代理>https://<host>/.insteadOf https://<host>/`，**两端都必须带协议**——裸主机会让重写静默失效），让 DSH 通过 pnpm/git 安装 GitHub 插件时无痕走代理（「安装源」只管 npm 包，覆盖不到 git clone 这条链路）。`mirror` 可省：省略时按候选清单顺序探测、取第一个可用的，仅清单为空或全部停用才必填；探测不通的地址不写入候选清单，只在返回的 `rejected` 里告知；清单外置 `lib/core/github-mirror/candidates.json`，失败累加满 3 次自动停用、`probe` 可恢复；`apply` 先探测后写并自动轮换、`dryRun` 缺省 true、`clear` 只删受管站点规则。`sync_plugin` 新增 `hmr` 参数：幂等启用 profile 的模块热重载（补 `- id: hmr`、`base` 用版本无关表达式、`root` 含 `local-plugins`），并回报该插件是否已可免重启。修「改了代码但工具没换新」的根因：工具注册与两个 post-execute 钩子都把 disposer 交回 cordis（`inject` 回调是子 fiber，不返回 disposer 则热重载后旧注册永不释放、同名重注册被拒，工具一直指向旧闭包）。README 版本记录移至本文件。 |
